### 三、算法在硬件里怎么实现

#### 3.1 活跃判断（简单）

48 个 16-bit 比较器：

```systemverilog
for (i = 0; i < 48; i++)
    active[i] = (grid_count[i] > active_threshold);
```

一拍出结果。**工作量：半天。**

#### 3.2 四连通合并（核心难点）

8×6 = 48 个网格，规模很小，用**多轮标签传播**最合适。

**算法：**

1. 初始：每个活跃网格有自己的标签（= 网格索引），不活跃的标为 `0xFFFF`。
2. 每轮：每个网格取"自己 + 上、下、左、右邻居"中的最小标签。不活跃的网格保持 `0xFFFF`。
3. 重复直到标签不再变化（最多几轮就收敛）。
4. 收敛后，同一连通区域的网格拥有相同标签。

**硬件实现：**

- 用 48 个 6-bit 标签寄存器（`label[0..47]`）。
- 每一轮传播用一个组合逻辑，一拍完成。
- 状态机：`IDLE → PROPAGATE → CHECK_STABLE → DONE`。
- 最多 48 轮，实际几轮就收敛。

**工作量：2–3 天。**

#### 3.3 最大区域选择（中等）

- 统计每个标签出现的次数。
- 找最大。
- 平局时优先更上、再优先更左（与你 Python 规则一致）。

**硬件实现：**

- 用一个计数器数组统计每个标签的出现次数。
- 然后线性扫描找最大。

**工作量：1 天。**

#### 3.4 ROI 外接矩形输出（简单）

- 找到最大区域的标签后，遍历 48 个网格，找 `min_grid_x`、`max_grid_x`、`min_grid_y`、`max_grid_y`。
- 输出 `(min_x × 80, min_y × 80, (max_x - min_x + 1) × 80, (max_y - min_y + 1) × 80)`。

**工作量：半天。**

#### 3.5 自适应机制

摘要里的"自适应"，最稳妥的解释是**根据图像内容动态调整阈值**。两种实现：

**方案 A（Python 自适应，FPGA 可配置）：**

- 加 AXI4-Lite 寄存器：`binary_threshold`、`active_threshold`。
- Python 侧计算图像的均值/方差/噪声估计，动态设置阈值。
- FPGA 接收新阈值，下一帧用新阈值。

**方案 B（FPGA 自适应）：**

- FPGA 内部统计整图 Sobel 幅值均值，根据均值动态调整阈值。
- 复杂度高，不推荐。

**用方案 A。工作量：1–2 天。**

### 五、自适应策略（Python 侧）

RTL 加完 AXI4-Lite 后，Python 侧加一个简单自适应：

```python
def adaptive_threshold(img):
    """根据图像梯度分布动态调整阈值"""
    gx = cv2.Sobel(img, cv2.CV_32F, 1, 0, ksize=3)
    gy = cv2.Sobel(img, cv2.CV_32F, 0, 1, ksize=3)
    mag = np.abs(gx) + np.abs(gy)
    
    # 用 Otsu 或百分位数
    binary_thr = int(np.percentile(mag, 70))  # 70% 分位
    binary_thr = max(40, min(120, binary_thr))  # 限制在 40-120
    
    # 活跃阈值也跟着调
    active_thr = int(768 * binary_thr / 80)
    
    return binary_thr, active_thr
```

然后通过 AXI4-Lite 写入 FPGA，下一帧生效。**这样"自适应"就名副其实了。**

### 工程实现必须注意的 3 个真实风险：

1. **带宽反压问题**：
   你现在的 `sobel_axis` 输出是一拍一个像素。新加的 DMA 如果搬运速度跟不上，`edge_m_axis_tready` 会拉低，导致整个流水线卡死，进而影响原来的 ROI 计算。
   **解决对策**：如果直接接 `1'b1` 跑不通，需要在 RTL 里加一个 AXI-Stream FIFO 作为缓冲，防止读取慢把上游卡死。
2. **DMA 读取对齐问题**：
   新的 8-bit DMA 接收 307200 字节，如果接收长度配置不对，或者 TLAST 没对齐，DMA 会死锁。
   **解决对策**：确保新增的 `edge_m_axis_tlast` 信号准确地在第 307200 个像素时拉高。
3. **时序可能再次崩溃**：
   增加一套 DMA 和相关连线，会改变原有的布线。你原有的 WNS 是 +1.286ns，加完之后，大概率会变负。
   **解决对策**：如果综合后 WNS 变负，直接去 Block Design 里把 FCLK_CLK0 降频到 50MHz。

这就是完整的纯硬件边缘图回传方案。没有任何模拟，没有任何原图，Python 拿到的就是 FPGA 内部 `sobel_axis` 模块当场算出来的 0 和 255 的矩阵。去改吧。
