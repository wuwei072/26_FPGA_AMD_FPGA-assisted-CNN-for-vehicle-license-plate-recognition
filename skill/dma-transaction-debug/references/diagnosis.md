# 按现象定位 DMA 问题

先保留一次失败的输入长度、输出长度预期、通道状态寄存器、IP 配置与驱动版本。表中寄存器仅适用于 AMD AXI DMA Simple 模式。

| 现象/触发条件 | 优先检查 | 不该直接得出的结论 |
|---|---|---|
| 发完但一路接收不结束 | 此路是否先启动；TLAST 是否在包尾；TKEEP 是否标识有效字节；RTL 是否在背压时保持 data/last | “增加超时一定能修好” |
| 所有通道都不推进 | DMA 时钟/复位、连线、AXIS 接收是否存在；是否遗漏某一路接收 | “FPGA 频率太低” |
| status 含 0x10 / 0x20 / 0x40 | 分别为内部、从端、地址译码错误；检查长度/流协议、DDR访问、物理地址 | “都是 TLAST 问题” |
| 显示旧帧或间歇性数据错误 | 接收缓存失效、输出是否仍是复用缓冲的 view、输入是否在 DMA 读取中被重写 | “一定是 Sobel/FFT 等算法错误” |
| 第二次调用失败 | 第一轮是否真的结束、驱动 wait 是否完成、同一 IP 是否被另一进程使用 | “第一次能跑说明接口永远没问题” |
| 接收字节数不等于契约 | 早到 TLAST、数据宽度/字节数混淆、输出条数错误 | “按缓冲容量解码剩余旧字节也没关系” |
| 更换位流后结果异常 | 同一构建的 bit+HWH，IP 名称和宽度是否变化，实际下载是否成功 | “文件名相同就是同一设计” |
| 主机画面卡但 DMA 正常 | 分别计采集、预处理、完整调用、编码、发送、显示；区分并行重叠时间 | “提高 PL 时钟必然提高显示帧率” |

## 状态读取示例

```python
print(f"MM2S DMASR: 0x{dma.mmio.read(0x04):08X}")
print(f"S2MM DMASR: 0x{dma.mmio.read(0x34):08X}")
```

完成后 `S2MM_LENGTH`（偏移 `0x58`）可用于核对实际接收字节数。先核对该 IP 版本手册，不能把这些偏移写到任意加速器控制寄存器上。读取 DMASR 不等于清除或恢复故障。

## 分层排查顺序

1. 用确定性小样本移除摄像头、网页、HTTP 等上层因素。
2. 核验软件提交的字节数与实际流格式，不要混淆元素数、像素数和字节数。
3. 核验先收后发及每一路接收都已准备。
4. 检查状态、完成长度、缓存与独立副本。
5. 仍有丢拍/错位再看 RTL 仿真或 ILA 的 TVALID/TREADY/TLAST。背压时必须保持未握手的数据。
6. 超时后先处理所有权与硬件恢复，再开展下一次实验。单纯重启界面不保证 PL 中的 DMA 已停止。

恢复方式由平台确定：有的平台可以停止 DMA 并复位流式上游，有的平台须重新加载设计或重新上电。不要在无法确认总线已停止时释放物理缓冲。
