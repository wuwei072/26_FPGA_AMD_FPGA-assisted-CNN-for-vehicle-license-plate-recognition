# 主机—目标机分层联调

## 适用范围

用于电脑与 Linux 嵌入式设备，或两台电脑分工运行的采集、计算、显示系统。排查跑错机器、上传目录不一致、设备占用和服务连接问题，不限定板卡或端口。文件配对以 `.bit/.hwh` 为例，可替换为自己项目的产物或省略。

## 使用方法

先记清每台机器的地址、终端、工作目录和启动命令：

| 角色 | 运行内容 | 连接方向 |
|---|---|---|
| 目标机 | 设备访问、采集和数据服务 | 接受主机连接 |
| 主机 | 显示客户端 | 连接目标机 |
| 可选后端 | 识别、数据库等服务 | 接受调用方请求 |

用 Python 3.8+，无需安装第三方包。在本技能目录修改 [examples/deployment.json](examples/deployment.json)：`os` 填 `windows/linux/darwin`，`files` 填相对应用目录的必需文件；`artifact_pairs` 填共同文件名前缀和后缀，可省略。`startup_hint` 只展示启动命令，脚本不会执行。

可选 `sha256` 格式为 `{相对文件名: 发布时记录的SHA256}`，应取自可信构建或发布清单。给可疑文件重新计算哈希，不能确认它的版本。

目标机示例（替换应用目录）：

```bash
python3 scripts/check_deployment.py --plan examples/deployment.json --role target --root /home/user/my_app --out target_check.json
```

主机检查改用 `--role host` 和主机应用目录；Windows 可用 `python`，例如 `--root D:\my_app`。检查应在对应机器执行。退出码 `0` 为静态检查通过，`1` 为发现不符；JSON 记录解析后的路径、文件长度及哈希。同名配对文件需同时匹配可信清单，才能确认版本；仍需另做设备功能测试。

随后按顺序排查：

| 检查层 | 操作 |
|---|---|
| 执行位置与文件 | 核对机器、shell、Python、实际目录和发布版本 |
| 资源归属 | 正常停止已确认的旧任务，释放摄像头、DMA 等独占资源 |
| 服务 | 保留启动日志，先修第一条异常，再确认进程和监听端口 |
| 网络与协议 | 核对客户端目标 IP、端口和路由，再检查防火墙、包头及请求格式 |

Linux 用 `ss -ltn`、Windows 用 `Get-NetTCPConnection -State Listen` 查看服务端监听。单客户端 TCP 服务优先用正式客户端验证，额外端口探测可能占住会话。按应用依赖启动后端、目标机服务，再启动主机客户端并发起一次小请求。

可复制的协作提示词：

> 请按 host-target-bringup 排查连接失败。我提供各机器角色、终端提示符、目录、启动日志和目标地址；请定位失败层，分别给出最少检查命令和预期结果。

## 问题来源与验证

工作流提炼自多机部署中的执行位置、目录、资源占用和版本核对问题：

| 现象 | 得到的规则 |
|---|---|
| Windows PowerShell 执行板端 `sudo` 命令，提示 Windows Sudo 禁用 | 先确认机器与终端 |
| 新上传目录中的异常仍指向旧目录，报 Overlay 缺失 | 打印最终解析路径，先查目录错配 |
| 重复启动提示“Dashboard 已经运行” | 独占任务保持单一所有者 |
| 硬件文件、源码及上传副本多次更新 | 用可信发布哈希核对文件身份 |

运行 `python scripts/selftest.py` 可复测。**5/5 项自测通过**，覆盖正确文件、错操作系统、错目录、配对文件缺失和可信哈希不符。测试使用合成文件；服务连接和设备功能需在实际部署环境验证。

## 失效条件

- 配置、角色或地址写错，脚本不能自动纠正；相同操作系统也不代表同一台机器。
- 静态检查不验证硬件设计、HWH 内容、驱动、权限和运行时依赖，不能代替板端测试。
- 不明进程或活跃 DMA 的处理需按平台流程确认；本工具不杀进程、不加载硬件或写寄存器。
