# 主机与目标机分层联调

先读 [README.md](README.md) 的适用范围、失效条件与证据记录。这个工作流不绑定板卡型号；`.bit/.hwh` 检查是可替换的 PYNQ 示例，不能据此声称支持所有厂商加载格式。

1. 从终端提示符、报错路径和启动命令判断当前机器与 shell。列出主机、目标机、可选识别服务三者各运行什么，避免在主机执行目标机的设备访问程序。
2. 核实实际上传目录和文件，以目标机上的实际工作目录为准。使用 `scripts/check_deployment.py` 检查本机角色、文件和可选发布哈希；脚本不执行启动命令、不加载硬件。
3. 检查摄像头、DMA、串口等独占资源是否仍由上一次任务持有。只停止已确认属于当前工程的旧任务。避免验证脚本与设备服务同时占用同一硬件。
4. 在服务所属机器上确认进程存活与监听端口，再查客户端目标地址、路由和实际协议连接。没有监听时，先修服务启动；已监听时再逐层查网络与应用握手。
5. 对程序启动、硬件下载、寄存器写入保持原有授权边界。修复一层后用最小实际请求复验，不因连接问题擅自重综合或重装整个环境。

交付一张“机器 / 终端 / 工作目录 / 启动命令 / 预期现象”表和当前阻塞层。说明哪些已检查、哪些仍待目标机验证，不把静态文件检查称为硬件通过。

可复制的协作提示词、离线验证范围和失效条件见 README。首次复用先用自己的部署配置运行文件检查，再验证实际服务连接。
