# 实时系统瓶颈定位

先读 [README.md](README.md) 的适用场景与限制，按下列顺序协助使用者，不直接把程序改成多线程。

1. 确认用户要优化的是处理吞吐、画面更新率还是画面新鲜度。记录算法、输入大小、运行模式及计时边界。
2. 用 `scripts/frame_probe.py` 包住已有调用，至少区分采集、计算完整调用、编码、UI 提交和整个循环。存在子阶段时保留嵌套关系；并行阶段不能直接相加。未经测量不要把浏览器绘制耗时算进 `render`。
3. 用 `scripts/analyze_trace.py` 汇总按模式分组的 JSONL，先检查最大耗时，再检查抖动和未覆盖区间。不要用 `1000 / DMA_ms` 宣称实际显示帧率。
4. 每次只改变一项：停止循环中的参考计算；分开测试两种图片编码；减少重复转换；减少 UI 更新；最后才评估线程或换显示端。分辨率等用户约束保持不变。
5. 二值图可用 `scripts/codec_probe.py` 验证 1-bit PNG：先确认值域，再解码逐像素比较并读取真实 PNG 位深。失败就保留原编码，不能先阈值化掩盖错误。
6. 每项改动使用相同输入、运行环境和采样方法；报告前后值与未知项。采集线程、网络线程不是免费加速，多线程效果差可恢复串行。
7. 保留与帧号绑定的图像、结果、耗时；可丢旧显示帧，但不能把旧 ROI 配给新图。异步请求使用有限并发/有限待处理量。

输出计时证据、瓶颈判断、最小改动和复测结果。实验提示词见 [references/workflow.md](references/workflow.md)。本技能用于软件数据通路分析，不修改 RTL。
