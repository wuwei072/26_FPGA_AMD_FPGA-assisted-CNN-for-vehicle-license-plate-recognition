# 可直接复制的协作提示词

## 定位卡顿

> 我有一个连续采样、计算和显示的程序。请先列出各阶段的计时起止点，不修改算法或分辨率。根据我提供的逐帧日志区分完整调用、子阶段、并行区间和 UI 提交。只选择证据最充分的一处瓶颈，给出一次最小实验和验收方法。没有记录的相机内部、网络或实际显示延迟请明确列为未知，不要换算成确定的显示 FPS。

需要提供：主循环、输入规格、进程/线程分工、是否开启参考模型、至少一段完整周期日志。缺哪项就先测哪项，不先猜根因。

## 验证一次优化

> 以下是相同输入和配置下的 A/B 日志，以及唯一改动。先检查输出是否等价，再按阶段比较均值、P95 和总循环。请指出是否有线程重叠、采样次数不足或其他配置变化；如果只能观察到相关性，不能写成单项改动的因果收益。保留没有改善或退化的结果，并提出保留或回退建议。

## 从 Notebook 迁移到桌面显示

> 我需要保留现有计算和数据契约，仅评估显示通路迁移。请先说明哪些计时已证实由显示/通信引起；区分网络收包、解码和 GUI 绘制线程。设计有限长度的待显示帧队列，图像、元数据和耗时使用同一 frame_id。不要更改算法，不要让 GUI 线程等待 HTTP，不要同时无限排队网络请求与历史视频帧。
